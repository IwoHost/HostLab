How it works

The whole format rests on one rule: every file is exactly 420,000 bytes. Not a target, not an average — a hard, constant size. That's impossible to do losslessly, so .420 is proudly lossy. The interesting part is spending those bytes well.

1. Bytes become a budget

420,000 bytes × 8 = 3,360,000 bits. Divide by the number of pixels and you get bits per pixel — the real currency of compression. A small image gets a fat budget per pixel and looks great; a huge image gets starved. So the first job is deciding how big the image should even be.

2. The 2D sweep

The naive way keeps your image full-size and just lowers quality until it fits. That's usually a mistake — a clean, slightly smaller image beats a full-size blocky one almost every time. So .420 searches a grid instead: several resolutions, each encoded in both WebP and JPEG, each binary-searched to land just under budget.

For each resolution × codec: shrink the image, binary-search the quality slider about seven times until the encode fits in 420,000 bytes, keep that survivor.

3. Judging with SSIM

Every survivor fits the budget, so which is best? You can't trust the raw quality number across different resolutions. Instead each candidate is decoded, scaled back to a common size, and compared to the original with SSIM — a perceptual metric that models how human vision weighs brightness, contrast, and structure. The highest SSIM wins. You can watch the whole race in the scatter plot on the Encode tab.

4. Optional cleanup

Noise is random, and random doesn't compress — the codec wastes bits drawing grain nobody asked for. An optional denoise pass smooths that away first. After shrinking, an optional sharpen pass restores a little perceived crispness. Both are off by default because they only help certain images.

5. Padding with personality

The winning image rarely fills 420,000 bytes exactly. Rather than pad with zeros, .420 fills the gap with an optional hidden second image (revealed by tapping the image when decoding) and a tiny Bytebeat formula — a one-line piece of math that generates an ambient hum, seeded from your file. Whatever's left is zero-filled to hit the magic number.

6. The container

It's wrapped in a 24-byte F420 header: magic bytes, version, which codecs were used, and the byte-lengths of the main image, the hidden image, and the hum. The decoder reads those offsets, slices out each piece, and ignores the padding. Older v1 files still open.
